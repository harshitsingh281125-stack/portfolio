The URL goes to POST /api/metadata, a server route, because the browser cannot fetch a cross-origin page and read its <title>.

A bookmark manager that makes you type the title is a form. The only input here is the URL; the server does the rest, which is what puts an SSRF surface in the middle of a CRUD app, and why the other tour exists.

fetchStatus is success only when title, description and image all arrived. Anything less is partial and the dialog says what is missing; the save still works.

The parse is a cascade with a named outcome. A page missing an og:image is not an error and is not silently pretended away: it comes back as partial, and the UI shows a thinner card rather than a broken one.

Tags: the page's own first, then rules

No model call. What the author declared leads; 127 rules over host, path, title and description fill the rest.

On a dev.to article the first step does the work: its own webdev, javascript, programming, beginners lead, and the rules add http, cookies.

Most platforms already publish their tags in machine-readable places, so reading them beats guessing. Rules cover pages that declare nothing. Same URL, same tags, every time, and every suggestion is editable before saving.

The constraint is the check. The app does not query first and then insert; it inserts, and reads 23505 as “show them the one they already have.” Lowercasing the path is deliberate and lossy: two URLs differing only in case are treated as one.

Asking "does this exist?" before inserting is a race with your own other tab. Here the database answers both questions at once: the unique constraint rejects the write, and the error code is specific enough to turn into a useful screen instead of "could not save".
