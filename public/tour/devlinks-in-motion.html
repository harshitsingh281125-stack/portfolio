A bookmark manager that makes you type the title is a form. The only input here is the URL; the server does the rest — which is what puts an SSRF surface in the middle of a CRUD app, and why the other tour exists.

fetchStatus is success only when title, description and image all arrived. Anything less is partial — the save still works, the card is just thinner.

The parse is a cascade with a named outcome. A page missing an og:image is not an error and is not silently pretended away: it comes back as partial, and the UI shows a thinner card rather than a broken one.

Tags are inferred by rule, not by a model

84 regexes over hostname, path, title and description. Same URL, same tags, every time.

Suggested
documentation react performance caching
documentation  ·  hostname is react.dev, a known docs host
react  ·  /\breact\b/i matched the path and the title
performance  ·  /\bperformance\b/i matched the description
caching  ·  /\bcach(?:ing|e)\b/i matched "cache a calculation"
No second network round trip, no per-save cost, and nothing to re-run when a model changes. The limit is honest: 84 rules is a vocabulary, not an understanding — a framework invented next year gets tagged by its hostname or not at all.

Tagging runs on every save, which is the frequent call, so it gets no inference at all. These four are what the rules actually return for this URL — run, not imagined. Suggestions are editable, which is the only reason a lookup table is an acceptable answer here.

The constraint is the check. The app does not query first and then insert — it inserts, and reads 23505 as “show them the one they already have.” Lowercasing the path is deliberate and lossy: two URLs differing only in case are treated as one.

Asking "does this exist?" before inserting is a race with your own other tab. Here the database answers both questions at once: the unique constraint rejects the write, and the error code is specific enough to turn into a useful screen instead of "could not save".

Sharing is the reason a bookmark manager is worth building rather than using a text file. Making it work by loosening a route handler would leave the rows reachable another way; the rule lives in Postgres, so every client gets it whether it asks for it or not.
